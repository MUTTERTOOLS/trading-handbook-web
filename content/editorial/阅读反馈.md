# 阅读反馈（伴读 ↔ 文稿 唯一交流接口）

> 本文件是伴读与文稿侧的**唯一**交流载体，格式即协议。
> **v2 入库路径（2026-11-19 负责人修订）**：伴读只产出条目草稿（随回报交付 + 存
> workbuddy 记忆层，**不写本文件**）；**条目由负责人交接**（上传文件/粘贴文本，
> 格式不限）后由编排者规范化写入本文件（初始状态待仲裁/待核验）；文稿：只实现
> "已采纳"条目并回写落稿记录；编排者/负责人：仲裁。除状态流转所必需的字段外，
> 任何一方不得改他方写下的文字。本文件在 `content/editorial/` 下，不参与站点
> 构建（srcExclude）。

## 状态机

```
待仲裁 ──负责人/编排者批准──▶ 已采纳 ──文稿落稿──▶ 已落稿（终态）
待仲裁 ──负责人/编排者驳回──▶ 已驳回（终态）
待仲裁/已采纳 ──数值事实须溯源──▶ 待核验 ──核验通过──▶ 已采纳｜核验不过──▶ 已驳回
已采纳 ──该章字数预算不足等──▶ 挂起（附原因，条件消失可回已采纳）
已采纳 ──文稿异议依据确凿──▶ 已驳回（终态，附依据）
已采纳 ──文稿异议拿不准──▶ 已退回（附异议+依据）──▶ 负责人/编排者重裁
                                     （重裁结果：修订后重采纳／驳回／挂起／转待核验）
已驳回 ──负责人复核推翻──▶ 已采纳（须注"负责人驳回复核 + 日期"）
```

各方可执行的状态流转：

- **伴读**（v2）：**不写本文件**；产出条目草稿（随回报交付 + 存 workbuddy 记忆层），
  草稿状态标待仲裁/待核验（讨论新得→待核验）；负责人会话内明确批准的条目在草稿中
  注"负责人批准 + 日期"，入库时由编排者据此置为已采纳。伴读不得自行批准。
- **文稿**：已采纳 → 已落稿（落稿记录填 commit + 一句改动说明）；撞该章字数预算
  → 挂起（附原因）；审查有**实质异议**时二选一——**依据确凿**（引用正文原文/
  红线条款/一致性冲突点）→ 直接转**已驳回**（终态，依据写入落稿记录）；
  **拿不准** → 转**已退回**呈负责人/编排者重裁。**不得静默降格实现或变相拒绝，
  不得按自己理解改写条目意图，不得无依据驳回**。负责人复核推翻（已驳回→已采纳）
  的条目必须实现，仍认为有问题只能走已退回并说明新依据，**不得再次自行驳回**。
- **编排者/负责人**：待仲裁 → 已采纳／已驳回／待核验／挂起（须注批准人 + 日期）；
  已退回 → 重裁（修订后重采纳／驳回／挂起／转待核验）；已驳回 → 复核推翻为已采纳。
