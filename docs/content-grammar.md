# 内容语法契约（content-grammar）

> 本文档是三层架构的**唯一接口**：文稿层（L1）据此写作，校验门禁（L2）据此执法，
> 渲染层（L3）据此实现。词汇表**封闭**：新增/修改/删除任何词汇必须走 §9 变更流程。

## 0. 三层与隔离

```
L1 文稿层   content/B*/*.md              纯 Markdown + 本词汇表，零 HTML
L2 契约层   本文档 + tools/content/check.ts    执法点（规则语义归本文档，代码实现归渲染侧任务）
L3 渲染层   apps/web/.vitepress/         词汇表 → 组件 / 链接 / 徽标 / 折叠
```

- 文稿 Agent 只见 L1 + 本文档；渲染 Agent 只见 L3 + 本文档 + §5.1 槽位清单。
- 渲染 Agent **禁止改动正文**；文稿 Agent **禁止改动 `tools/`、`apps/`、`docs/`**。
- 两层不共享实现上下文，只共享本文档。词汇表变更四处同步：**本文档 + 插件 + 校验器 + 槽位注册表**，仲裁归编排者。

## 1. 文件布局与路由

| 位置 | 说明 |
|---|---|
| `content/B{1..8}/B{n}-C{xx}.md` | 77 章正文（唯一内容源） |
| `content/B{n}/{章id}_delivery.md` | 交付说明（编辑侧，不参与站点渲染，校验器要求存在） |
| `content/series.yaml` | 丛书元数据：分册顺序、slug、期望章数 |
| `content/index.md`、`content/[volume].md` | 站点首页与 8 个分册落地页（文稿侧） |
| `content/[volume].paths.ts` | 动态路由生成器（**渲染侧架构例外**：框架要求位于 srcDir，归渲染侧） |
| `content/editorial/**`、`content/dist/**` | 不参与站点，`srcExclude` 排除 |

章路由（目标态）：`/b{册}/c{两位章号}`，如 `/b3/c04`。
分册落地页：`/b{册}`。旧地址 `b1.html`~`b8.html`、`b1-map.html`、`risk-math.html` 保留为跳转页。

## 2. frontmatter 词汇表

标准 `---` 开头的 YAML，字段封闭：

| 字段 | 类型 | 约束 |
|---|---|---|
| `chapter_id` | string | 形如 `B1-C01`，与文件名一致 |
| `title` | string | 章标题，渲染为页 h1 |
| `prerequisites` | string[] | 前置章 id |
| `new_terms` | string[] | 新术语，**≤ 8 个**（超限报错） |
| `formulas` | string[] | 本章公式标识 |
| `constants_used` | string[] | 引用的常量标识（如 `EX-A`） |
| `status` | string | 必须为 `final` |

schema 定义在 `packages/content-model/`（zod），校验器与渲染层共用。

## 3. 固定小节

每章正文必须依次包含以下 10 个 `##` 小节，缺一即校验失败：

`开场问题` · `一句话结论` · `本章学习目标` · `正文` · `常见误区` · `本章小结` ·
`自测题` · `速查卡`（允许带括号副标题）· `延伸与链接` · `⚠️ 风险提示`（允许前缀）

## 4. 行内词汇

| 词汇 | 语义 | 渲染语义（L3） |
|---|---|---|
| `〔B{n}-C{nn}〕` | 交叉引用 | 转为指向 `/b{n}/c{nn}` 的链接；校验器要求目标章存在 |
| `【待核验】` | 待核验标记 | 黄色徽标；站点级计数一致 |

## 5. 容器词汇

### 5.1 `::: interactive` —— 交互组件槽位

```markdown
::: interactive ThreeQuestions
:::
```

- 容器体内**为空**；组件实现与槽位 id 的绑定由渲染侧注册表决定，内容层不感知组件细节。
- 槽位 id **冻结清单**（6 个）：`ThreeQuestions` / `ExpectancyExplorer` / `RecoverCurve` /
  `PositionCalculator` / `GapConstraint` / `DrawdownStreak`
- 未知槽位 id：校验器与渲染插件**都必须报错**。
- 约束：同一章内同一槽位至多出现一次；不同槽位可共存一章（现状每章仅一个）。
- 现存落位（7 处）：B1-C01、B1-C03、B3-C01、B3-C04、B3-C06、B3-C08、B3-C10。

### 5.2 `::: figure-spec` —— 绘图说明

```markdown
::: figure-spec
（绘图制作提示的正文）
:::
```

- 容器体是**制图规格**（提示词 + mock 数据），供制图与校验使用，
  **不进入读者渲染输出**（2026-11-17 D12 修订；此前为可折叠说明区块）。
- 成品图配对约定（已拍板）：查找键 `<章id>-fig<n>`（按章内出现顺序编号），
  成品目录 `apps/web/public/figures/<章id>-fig<n>.svg`；注入原则
  **"有图默认可见内联，无图整块不渲染"**。
- 图注文案不是本词汇的组成部分；如需图注，按 §9 立项。

### 5.3 `::: qa-cards` —— 问答卡片（2026-11-19 §9 立项，F-007）

```markdown
::: qa-cards 说法一"跟主力做波段"过得了筛子吗？
一问：赚谁的钱？——能答，赚情绪化交易者的钱。
二问：对方为什么持续让出？——能答，贪婪恐惧让对手在差时点成交。
三问：我凭什么比对方强？——答不上。
结论：卡在第三问，不采信。
:::
```

- 容器体由若干**对答行**加**至多一条结论行**构成：对答行以"序词＋全角冒号"开头
  （序词常用"一问/二问/三问"，亦可用"问"），结论行以 `结论：` 开头。
- 参数行（卡头）为该组的题句或说法名；相邻多个 qa-cards 容器渲染为同组连排卡片。
- 渲染为问答卡片组件：卡头带分隔线（衬线加重＋序号），对答行缩进、问句关键词册色
  加重，结论为册色淡底卡带"结论"标签，hover 上浮（与站点卡片交互语言一致）。
  视觉规格存档：`content/editorial/mockup-qa-cards.html`。
- **适用边界（编辑规则，防滥用）**：仅当单段内含三组以上问答对且无结构化标题时
  才允许转卡片；禁止把一般段落卡片化。
- 校验器：容器闭合校验＋容器体至少一条对答行；未知容器类型报错规则同样适用。
- 现存落位（2 处，2026-11-20 转换）：B1-C04 §四、B1-C02 §来源三问演示。

### 5.4 `::: layer-map` —— 分层结构图（2026-11-24 §9 立项，结构图组件家族）

```markdown
::: layer-map 道、法、术：三层分工——底层承载上层
层 道（认知层）：回答"该不该做"——钱从哪来、亏得起多少
道·产出：说得清的收益来源＋亏得起的底线
道·改动成本：最难改——错了要推倒重来
层 法（规则层）：回答"怎么做"——把认知写成书面规则
法·产出：可执行、可对账的条文
层 术（工具层）：回答"看什么"——给规则空格填数的手段
术·改动成本：最常换——如换窗帘不换承重
底座：册二市场规则与品种——不属于三层，但三层都建在它上面
:::
```

- 参数行（图题）为该图标题。容器体由三类行式构成，**层行按显示顺序（自上而下）书写**：
  **层行** `层 {层名}（{层副名}）：{一句话}`——定层名与默认收起时的一句摘要；
  **字段行** `{层名}·{字段名}：{内容}`——挂到对应层的展开详情，每层 1~4 条；
  **底座行** `底座：{内容}`——至多 1 条，置于体末，渲染为图内虚线注记。
- 渲染为堆叠层组件：默认收起只显层名＋一句话；悬停/点击展开字段详情（点击可钉住，
  键盘可达）；层间用册色深浅区分，浮现动画可重播并尊重减动效偏好。色规落点：
  **仅册色深浅，不引入语义色**（分层是结构属性，不用红黄绿渲染）。
  视觉规格存档：`content/editorial/mockup-diagrams.html` 组件一节。
- **适用边界（编辑规则，防滥用）**：仅当正文存在实质的分层结构——≥2 层、层间为
  承载/归属关系（地基-结构类）且正文对该结构有实质展开——才允许转换；禁止把一般
  并列段落分层化。
- 校验器：容器闭合校验＋层行 ≥2＋字段行的层名须已由层行声明＋底座行 ≤1＋未知行式报错。
- 现存落位：立项时暂无；试点转换（B1-C05）后由编排者回填。

### 5.5 `::: flow-steps` —— 流程步骤图（2026-11-24 §9 立项，结构图组件家族；线性递进为其无分支形态）

```markdown
::: flow-steps 五步决策顺序——不通过就不进入下一步
步 ①看环境（时/风）：输入 指数与板块状态、事件窗口 → 输出 一句环境判断｜不通过 今天不做
步 ②选结构（工具）：输入 环境判断、标的池 → 输出 买入逻辑＋失效点｜不通过 换标的或放弃
出口：今天这笔不做（写入记录）
分界：③④之间 盘前｜盘中；⑤旁 盘后
演示 跳①②倒③：先买后找止损——止损被仓位倒逼
:::
```

- 参数行（图题）为该图标题。容器体行式：
  **步行**以 `步 ` 开头，后接步名（通常含序号字如"①看环境"，可带全角括号注记），
  冒号后为可选段序列——`输入 …`、`→ 输出 …`、`｜不通过 …` 的任意组合，至少一段；
  **出口行** `出口：{内容}`——至多 1 条，渲染为底部统一出口框；
  **分界行** `分界：{内容}`——至多 1 条，渲染为步骤间分界章；
  **演示行** `演示 {路径名}：{代价}`——错误顺序演示的数据源。
- **无分支形态（线性递进）**：全部步行不含 `｜不通过` 段且无出口行时，渲染为
  简洁线性步骤流（无菱形分支与统一出口框）。线性递进步骤（"第一步…第二步…"式）
  按此形态使用，无需另行扩词汇。
- 渲染为竖向流程组件：步骤号＋名称＋信息类别注记＋"输入→输出"小字；含不通过段时
  左侧菱形"不通过"分支线汇入统一出口框；点击步骤高亮其汇流路径；演示开关切换
  错误顺序演示。色规落点：红＝不通过/停手、黄＝错误顺序警示、正向流转＝墨线，
  **零绿色**，遵 §6 图表分级色规。视觉规格存档：
  `content/editorial/mockup-diagrams.html` 组件二节。
- **适用边界（编辑规则，防滥用）**：仅当正文明确给出步骤序词与先后约束（顺序不可
  交换、跳过有语义后果）才允许转换；一般"首先…其次…"的时间叙述不强行走步骤化；
  线性形态用于序词明确但无分支判定的递进。
- 校验器：容器闭合校验＋步行 ≥2＋含 `｜不通过` 段时出口行必填且恰 1 条＋出口行、
  分界行各 ≤1＋未知行式报错。
- 现存落位：立项时暂无；试点转换（B3-C03，连同两条绘图说明与对应成品图退役）后
  由编排者回填。

## 6. 全局纪律

1. **零 HTML**：md 源文件不得出现任何 HTML 标签。配置显式 `markdown: { html: false }`，
   校验器加"零 HTML"规则兜底。
2. **禁用词**：`稳赚` `必涨` `圣杯` `保本` `无风险` `跟我买` `六元` `门派一~四` `悟道`
   `出神入化` `一眼看穿`。豁免：引号内引用、驳斥/防骗语境（校验器 CRITICAL_MARKERS 表）、
   书名号内引用。
3. **字数（双层，2026-11-20 选读层立项）**：
   - **主体层**：延伸与链接节以外的读者可见字符，2400~8000；<2400 报错，
     >8000 警告（总编批准可保留）。超限处置沿既有阶梯（下沉/去重/拆章/备案）。
   - **选读层**：`## 延伸与链接` 节体（标题行起，至下一个 `## ` 标题行前——即
     ⚠️ 风险提示之前）的可见字符，**软上限 1200**（>1200 警告，总编批准可保留），
     无下限。
   - 选读层性质限定（防滥用）：只收数据锚点与来源备注、细节展开与非主线机制
     说明、延伸阅读推荐与互链、压缩切口回填四类；主体主线论证与必备小节实质
     内容不得移入；编排者验收抽查。
   - 可见口径剔除规则不变：frontmatter 块（含围栏）、`::: figure-spec` 容器整体
     （开栏行 + 容器体 + 闭栏行——制图说明不进渲染输出，见 §5.2）、
     `::: interactive` 容器行（空容器体，含闭栏行）照旧剔除；
     qa-cards、layer-map、flow-steps 容器体属读者可见内容，计入主体层
     （参数行计入，`:::` 围栏行不计，同 qa-cards 现行口径）。
   - 2026-11-19 修订：原"全文非空白"口径把制图说明等不可见文本计入"正文"，
     多图章被隐形惩罚（14 条警告中 4 条属口径假象），修正为可见口径。
   - 2026-11-20 立项（负责人分层提议：骨架/血肉）：双层拆分让主体保密度、
     压缩切口的血肉有家；实测 77 章落地后主体超限仅 B3-C09 一章（既有备案
     语义平移）、选读超软上限 0 章。设计文稿见
     `content/editorial/设计文稿-选读层.md`。
4. **禁全角感叹号**：正文不得出现 `！`。
5. **图表分级色规**（2026-11-16 修订）：界面与示意图——红 = 禁止/停手，黄 = 警示，
   不用红绿暗示盈亏；行情数据类图（K线/热力图/涨跌表）允许惯例配色（如 A股红涨绿跌），
   但强制图注声明惯例差异（"A股红涨绿跌；海外惯例相反"）；任何图不得用红绿渲染
   收益承诺或情绪诱导。
6. **数值约定**：规则/费率类数值标 `【待核验】`；个人化参考值注明"起步参考值，需个人校准"；
   计算器类演示须明示"算术演示，不构成投资建议"。

## 7. 校验门禁（L2 执法点）

`tools/content/check.ts`（`pnpm content:check`），规则清单：

1. frontmatter schema 校验（§2）+ `status === final`
2. 10 个固定小节完整（§3）
3. 字数上下限（§6.3）
4. `new_terms ≤ 8`
5. 每章存在 `*_delivery.md`
6. 正文零全角感叹号
7. 禁用词 + 语境豁免（§6.2）
8. 交叉引用目标章存在（§4）
9. 容器词汇合法性：`:::` 类型在白名单内、`interactive` 槽位 id 在冻结清单内、
   同章同槽位唯一（**返工新增项**）
10. 零 HTML（**返工新增项**）

## 8. 渲染语义要求（L3）

- 插件族把 §4/§5 词汇转为呈现；**未知容器类型必须报错**，不得静默透传。
- 槽位注册表 `Record<SlotId, Component>`：缺项或多余项**编译期报错**。
- 组件按需异步加载；echarts 仅从 `echarts/core` 按需注册；无组件页面不下载 echarts。
- 交叉引用生成的链接必须是 rewrite 后真实存在的路由（死链检查须通过）。

## 9. 词汇表变更流程

提案 → 编排者仲裁 → **四处同步**（本文档 + markdown-it 插件 + 校验器 + 槽位注册表）
→ `pnpm check` 全绿 + `pnpm build` 死链零错 → 变更完成。
任何一层不得单独引入词汇表外语法。

**组件词汇条目三件套（2026-11-24 负责人批，"组件供给协议"成文）**：凡新增
"内容声明数据 → 组件"类词汇（qa-cards、layer-map、flow-steps 及后续同族），
契约条目必须三件齐备，缺一不得立项：

1. **格式定义**——内容层怎么写：行式语法与参数行，配一个取自真实章内容的最小示例；
2. **渲染语义**——读者看到什么：组件形态、交互行为、色规落点，视觉规格存档于
   `content/editorial/mockup-*.html`；
3. **适用边界**——何时禁用：防滥用条款，仅当正文满足条目声明的结构特征才允许
   转换，禁止一般段落组件化。

配套分工（既有纪律成文）：渲染侧供实现与视觉规格（大型组件先出纯 HTML 静态稿
呈项目负责人审核）；编排者执笔契约条文并抽查落稿；文稿侧照契约按需使用。
**使用说明的唯一家是本文档**，不得散落任务书、清单或会话记录。
