# 内容语法契约（content-grammar）

> 本文档是三层架构的**唯一接口**：文稿层（L1）据此写作，校验门禁（L2）据此执法，
> 渲染层（L3）据此实现。词汇表**封闭**：新增/修改/删除任何词汇必须走 §9 变更流程。

## 0. 三层与隔离

```
L1 文稿层   content/B*/*.md              纯 Markdown + 本词汇表，零 HTML
L2 契约层   本文档 + tools/content/check.ts    执法点（规则语义归本文档，代码实现归渲染侧任务）
L3 渲染层   apps/web/.vitepress/         词汇表 → 组件 / 链接 / 徽标 / 折叠
```

- 文稿 Agent 只见 L1 + 本文档；渲染 Agent 只见 L3 + 本文档 + §5.1 槽位清单。
- 渲染 Agent **禁止改动正文**；文稿 Agent **禁止改动 `tools/`、`apps/`、`docs/`**。
- 两层不共享实现上下文，只共享本文档。词汇表变更四处同步：**本文档 + 插件 + 校验器 + 槽位注册表**，仲裁归编排者。

## 1. 文件布局与路由

| 位置 | 说明 |
|---|---|
| `content/B{1..8}/B{n}-C{xx}.md` | 77 章正文（唯一内容源） |
| `content/B{n}/{章id}_delivery.md` | 交付说明（编辑侧，不参与站点渲染，校验器要求存在） |
| `content/series.yaml` | 丛书元数据：分册顺序、slug、期望章数 |
| `content/index.md`、`content/[volume].md`（+ `.paths.ts`） | 站点首页与 8 个分册落地页 |
| `content/editorial/**`、`content/dist/**` | 不参与站点，`srcExclude` 排除 |

章路由（目标态）：`/b{册}/c{两位章号}`，如 `/b3/c04`。
分册落地页：`/b{册}`。旧地址 `b1.html`~`b8.html`、`b1-map.html`、`risk-math.html` 保留为跳转页。

## 2. frontmatter 词汇表

标准 `---` 开头的 YAML，字段封闭：

| 字段 | 类型 | 约束 |
|---|---|---|
| `chapter_id` | string | 形如 `B1-C01`，与文件名一致 |
| `title` | string | 章标题，渲染为页 h1 |
| `prerequisites` | string[] | 前置章 id |
| `new_terms` | string[] | 新术语，**≤ 8 个**（超限报错） |
| `formulas` | string[] | 本章公式标识 |
| `constants_used` | string[] | 引用的常量标识（如 `EX-A`） |
| `status` | string | 必须为 `final` |

schema 定义在 `packages/content-model/`（zod），校验器与渲染层共用。

## 3. 固定小节

每章正文必须依次包含以下 10 个 `##` 小节，缺一即校验失败：

`开场问题` · `一句话结论` · `本章学习目标` · `正文` · `常见误区` · `本章小结` ·
`自测题` · `速查卡`（允许带括号副标题）· `延伸与链接` · `⚠️ 风险提示`（允许前缀）

## 4. 行内词汇

| 词汇 | 语义 | 渲染语义（L3） |
|---|---|---|
| `〔B{n}-C{nn}〕` | 交叉引用 | 转为指向 `/b{n}/c{nn}` 的链接；校验器要求目标章存在 |
| `【待核验】` | 待核验标记 | 黄色徽标；站点级计数一致 |

## 5. 容器词汇

### 5.1 `::: interactive` —— 交互组件槽位

```markdown
::: interactive ThreeQuestions
:::
```

- 容器体内**为空**；组件实现与槽位 id 的绑定由渲染侧注册表决定，内容层不感知组件细节。
- 槽位 id **冻结清单**（6 个）：`ThreeQuestions` / `ExpectancyExplorer` / `RecoverCurve` /
  `PositionCalculator` / `GapConstraint` / `DrawdownStreak`
- 未知槽位 id：校验器与渲染插件**都必须报错**。
- 约束：同一章内同一槽位至多出现一次；不同槽位可共存一章（现状每章仅一个）。
- 现存落位（7 处）：B1-C01、B1-C03、B3-C01、B3-C04、B3-C06、B3-C08、B3-C10。

### 5.2 `::: figure-spec` —— 绘图说明

```markdown
::: figure-spec
（绘图制作提示的正文）
:::
```

- 渲染为可折叠区块；折叠与否不影响正文阅读。
- 成品图配对约定（已拍板）：查找键 `<章id>-fig<n>`（按章内出现顺序编号），
  成品目录 `apps/web/public/figures/<章id>-fig<n>.svg`；注入原则
  **"有图显图，无图只渲染折叠说明"**。

## 6. 全局纪律

1. **零 HTML**：md 源文件不得出现任何 HTML 标签。配置显式 `markdown: { html: false }`，
   校验器加"零 HTML"规则兜底。
2. **禁用词**：`稳赚` `必涨` `圣杯` `保本` `无风险` `跟我买` `六元` `门派一~四` `悟道`
   `出神入化` `一眼看穿`。豁免：引号内引用、驳斥/防骗语境（校验器 CRITICAL_MARKERS 表）、
   书名号内引用。
3. **字数**：章非空白字符 2400~8000；<2400 报错，>8000 警告（总编批准可保留）。
4. **禁全角感叹号**：正文不得出现 `！`。
5. **图表颜色**：不用红绿暗示盈亏；红 = 禁止/停手，黄 = 警示。
6. **数值约定**：规则/费率类数值标 `【待核验】`；个人化参考值注明"起步参考值，需个人校准"；
   计算器类演示须明示"算术演示，不构成投资建议"。

## 7. 校验门禁（L2 执法点）

`tools/content/check.ts`（`pnpm content:check`），规则清单：

1. frontmatter schema 校验（§2）+ `status === final`
2. 10 个固定小节完整（§3）
3. 字数上下限（§6.3）
4. `new_terms ≤ 8`
5. 每章存在 `*_delivery.md`
6. 正文零全角感叹号
7. 禁用词 + 语境豁免（§6.2）
8. 交叉引用目标章存在（§4）
9. 容器词汇合法性：`:::` 类型在白名单内、`interactive` 槽位 id 在冻结清单内、
   同章同槽位唯一（**返工新增项**）
10. 零 HTML（**返工新增项**）

## 8. 渲染语义要求（L3）

- 插件族把 §4/§5 词汇转为呈现；**未知容器类型必须报错**，不得静默透传。
- 槽位注册表 `Record<SlotId, Component>`：缺项或多余项**编译期报错**。
- 组件按需异步加载；echarts 仅从 `echarts/core` 按需注册；无组件页面不下载 echarts。
- 交叉引用生成的链接必须是 rewrite 后真实存在的路由（死链检查须通过）。

## 9. 词汇表变更流程

提案 → 编排者仲裁 → **四处同步**（本文档 + markdown-it 插件 + 校验器 + 槽位注册表）
→ `pnpm check` 全绿 + `pnpm build` 死链零错 → 变更完成。
任何一层不得单独引入词汇表外语法。
